# E-motel workspace design

Visual references: `frontdesk-concept.png` and `housekeeping-concept.png`, created with the built-in image-generation tool.

The concept briefs requested a complete desktop front desk room table and a mobile housekeeping task list. Both preserve the existing report-date, checkout, completion, notes, assignment, import and authorization workflows. Text and controls are implemented as React/HTML; these PNGs are design references only.

## Tokens and components

- Cool gray page `#f5f7fa`, white surface `#fff`, navy text `#172b4d`, muted text `#64748b`, border `#dce3ed`, action blue `#2563eb`.
- System sans typography: 32px desktop / 28px mobile page titles, 22px section titles, 13–15px operational text, 30px desktop / 24px mobile housekeeping box numbers, 20px desktop room numbers.
- 12px surface corners, 8px controls, 16px mobile gutters, 40px desktop gutters, housekeeping room boxes at least 84px tall.
- Housekeeping box tones: solid red `#dc2626` (dirty) and solid blue `#2563eb` (stayover service not done) are work to do; light amber `#fef3c7` (waiting for checkout), light green `#dcfce7` (clean / service done) and striped gray (unavailable) are not. Labels and icons repeat each meaning so color is never the only cue.
- Shared horizontal navigation, status totals, underline filter tabs, colored status labels, room search, report-date controls, disclosure filters, inline notices, room editor and error/empty states.
- Housekeeping shows one colored box per room, four per row on most phones and more on wider screens, with sticky, horizontally scrolling top tabs for **Ready to clean** (the default, vacant dirty rooms only), **Services** (all stayovers), **Waiting for checkout**, **Done**, and **Unavailable**. The selected tab keeps its color key and notes list. Tapping a red or blue box completes it; completed cleaning leaves the ready list and appears in **Done**, while completed stayovers remain green in **Services**. Messages and immediate **Undo** sit in a fixed bar at the bottom. Completed room boxes also keep a 44px **Revert** button, so staff can correct an action after dismissing the message. Front desk uses six aligned table-style columns on desktop and stacked room entries below 800px.
- Front desk also offers a Table / Boxes switch beside room search. Boxes are the default and use a compact responsive grid with room number, status and checkout/edit actions; guest/stay, attendant and full notes expand under Room details. Phones show two cards per row. The initial queue contains only guests waiting for checkout, with continuing stayovers in their own filter. Status sorting puts checkout rooms first. The browser remembers the choice. Both layouts share the same filters, live data and active draft; switching views does not reload rooms or discard edits. An editing card spans the grid so all form fields remain comfortable to use.

## Content and workflows

Headings: Housekeeping, Ready to clean, Stayover services, Waiting for checkout, Done, Unavailable, Notes, Front desk, Room board. Primary actions: tap a red or blue room box, Undo, Revert, Check out, Edit, Save, Upload morning PDF, Refresh rooms. Front desk status labels: All rooms, Waiting for checkout, Ready to clean, Stayovers, Done, Unavailable. Select rooms enables occupied-room bulk checkout on the desk, and bulk clean/service/revert on housekeeping. Selection clears when its visible scope changes, preserves eligible failed actions for retry and drops rooms whose live task type changes. Housekeeping box labels: Dirty, Checkout, Occupied, Clean, Out of Order / Maintenance, Not done, Done. Navigation: Front desk, Housekeeping, Upload PDF, Room sheets, Sign out, limited by existing role permissions.

Intentional adjustments to generated references: remove invented Dashboard/Rooms/Reports mobile navigation; retain authorized app navigation. Keep the complete Waiting for checkout label rather than shorten it. Retain one existing More filters and report tools disclosure, plus previous/next/Today date controls, instead of creating unrelated tools or sortable column controls. Counts, dates and room details always come from application data. All room notes remain readable rather than truncated.

Saved work and board synchronization have separate outcomes. A failed secondary sync keeps the completed action and shows a persistent **Retry sync** control. Retry applies the exact saved action only while the room's state and version still match; a newer guest or staff change requires review. Ordinary notifications can be dismissed without losing repair access, and reviewed sync warnings have their own dismiss control. Bulk workers recheck each queued room and skip changed records. Version checks and conditional writes also protect both boards on the server, while late HTTP responses preserve newer live data.

Live events share existing authenticated Socket.IO sessions. Updates apply only to the displayed report date, older versions cannot overwrite newer records, and reconnecting refreshes the authoritative board. When disconnected, the connection label explains the 30-second fallback checks.
